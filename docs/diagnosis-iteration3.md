# 噪声失配与低冗余诊断改进验证

本轮只处理算法、输入输出兼容性和回归验证，未更新交付包、报告展示或演练材料。**尚不能判定六星各项指标全部通过**。七星、普通解、课程接口和公开数据通过；六星冷启动、快速换星的部分细分场景仍未达到精度线。以下保留失败，不用总体平均掩盖它们。

## 实际修改

- `core/noise.py`：以不重叠历元对的全星奇偶空间残差差分估计噪声。设当前零空间基为 U，前历元投影为 S，则差分协方差为 σ²(I+UᵀSU)，先白化再取平方和。窗口最多 32 对，使用卡方中位数标定尺度和二项分布次序统计检验；至少 3 对且有证据拒绝名义尺度时才增大尺度。当前检测只使用此前完成的历元对。固定单星偏差一阶抵消，单次跳变不能控制中位数。没有选择“最小残差子集”来估计噪声。
- `core/diagnosis.py`：累计证据未达到确认门限时，也允许其领先候选作为暂定解，但须通过当前检验且没有强反证。保持 SUSPECT，与身份确认分开；现有断续、换星和幅度创新重置保留。减少弱可辨识情况下逐历元最小残差的反复跳动。
- `core/solver.py`：唯一通过的单星子集仍须满足相对证据要求才能确认。新增候选故障方向相关系数、最近竞争卫星和夹角。所有改进位置仍由当前保留观测独立拟合；不存储位置约束，不使用真值、未来观测或卫星专属参数。
- `SolverConfig`：阻止非整数预算、非法迭代次数、NaN/无穷或非正数收敛/PDOP 参数绕过数值检查。新增可关闭的噪声适应、严格确认和弱历史选择开关，配置随运行保存。
- 既有 GNC 日志视图只计入 GNC 提议，避免把新增噪声诊断记录误称为 GNC 搜索。没有新增展示流程。

噪声尺度是工程估计，有限窗口、快速相关误差和启动阶段不能当作已知高斯噪声或航空级完好性保证。中位数抗个别污染的依据参考 [NIST 的稳健尺度说明](https://www.itl.nist.gov/div898/software/dataplot/refman2/auxillar/mad.htm)；本实现采用径向卡方中位数及白化，而非直接套用逐星 MAD。故障检测与排除的区别可参阅 [ESA RAIM Algorithms](https://gssc.esa.int/navipedia/index.php/RAIM_Algorithms)。

六星连续全部强故障段 P95 从 9.535 降到 5.705 m，成功率95.07%→96.14%；全部错误剔除347→247，确认错误仍有3个。正确标记率96.39%，其中确认正确率仅88.05%，其余是尚未确认的正确暂定标记。孤立首历元没有历史，不能受益于噪声估计或历史选择：31次错误暂定剔除均为SUSPECT，确认错误0；这不代表这31个位置正确。

六星冷启动失败主要集中于低故障可观测性和近共线故障方向：部分30 m偏差仍落在全局残差门限内，另一些候选即使连续观察仍难区分。不能将其都归咎于代码缺陷，也不能据此宣称没有进一步研究空间。

## 高噪声压力结果（超出教师 0.8 m 模型）

真实噪声2.4 m、配置名义尺度仍为1 m；新方法自动估计而非读取生成标签。

| 指标 | 上轮默认 | 本轮默认 |
|---|---:|---:|
| 所有无故障历元误报率 | 29.57% | 3.73% |
| 纯正常场景误报率 | 31.07% | 3.48% |
| 共同偏差场景误报率 | 28.39% | 3.35% |
| 全部错误剔除次数 | 3625 | 1049 |
| 确认错误剔除次数 | 961 | 128 |
| 全部10 m内成功率 | 80.80% | 88.37% |

这是稳健性改善，**不是高噪声全指标通过**。高噪声正常P95=6.872 m，故障精度与检出率仍不足；阶跃、渐变场景各自的短正常段误报率约9%，启动校准仍有代价。全部明细保留，未只报告有利分组。

## 为什么不能保证任意六星首历元达标

已构造两个符合本题四未知数模型的单星强故障状态：G07 −120 m与G28 +45.59 m；接收机椭球高分别161.50 m和63.04 m。两位置水平距离128.64 m，六条无噪声伪距均值向量的欧氏距离仅0.142 m，小于0.8 m单星噪声。

在相同独立高斯噪声、两个状态等先验的二选一问题下，即使知道只有这两种可能，最优判别的理论错误率仍为 Φ(−‖Δμ‖/(2σ))≈46.47%。两个10 m位置邻域彼此分离，因此不能同时保证两个场景95%的10 m定位成功率。这是限制“对任意六星首历元作保证”的反例，不是拿来解释所有失败或代替实测指标。详见 [完整构造](../runtime/diagnosis-iteration3/cold-identifiability.json)；构造仅用于事后分析，求解器不读取它。

任务书也要求在证据不足时准确表达限制。当前软件以SUSPECT、未确认原因与全部候选证据表达这一点，没有将所有候选标为故障，没有加入固定坐标/高度约束，也没有删除不利历元。
