# 现场演示与答辩准备

以实际结果核验模型理解。以下是建议流程，不代表成员已经完成答辩，也不替代老师未公布的测试。

## 启动

源代码首次安装参见 README。交付包已含本次构建的 `web/dist`，安装 Python 依赖后可直接启动，无需现场重新安装 Node：

```bash
uv sync --locked
uv run gnss serve
```

打开 http://127.0.0.1:8000。全部计算与记录保存在本机。首次同步依赖需要网络；提前安装后可用 `uv run --offline gnss serve` 预演离线启动。

## 建议的六分钟演示

1. 选择 D02 正常动态观测，批量计算。查看600历元、“水平误差P95”约1.59m（标注“仿真 · 全程”）、有效解比例100%。解释轨迹以首次有效解为ENU原点，和真值误差不同。
2. 选择 D03 异常演示。通过底部“状态回放”选择历元120–179的异常区段。点击轨迹或钟差图定位历元，坐标、残差和证据同步更新；切换逐星诊断，点击卫星表或天空图的G19，查看残差、候选阈值和剔除结果。切到下一段观察恢复；分别查看四星、少星、无观测状态。
3. 在实验设计页换一颗目标卫星、改为负偏差或渐变，重新运行。说明运行前只设实验条件，解算器看不到故障标签和未来观测。关闭故障检测并重跑，核对普通/改进结果相同。
4. 导入教师提供的课程JSONL及配套导航。确认单位、GPS周和秒。未知数据没有独立真值时不显示绝对精度评分；从实际残差和状态说明结果。
5. 按 README 的 TCP 回放命令加入暂停。暂停后“历史位置”提示保留；收到新的有效历元后才更新当前位置。导出CSV检查每历元一行，0/3星坐标为空。
6. 展示报告成功案例与失败案例，说明多假设方法为何作为默认值，GNC为何保留实验选项。最后从历史记录回看一次运行，展示输入、参数和诊断日志。

若演示时间有限，先完成1、2、3，再用独立TCP预演记录解释5。不要只展示准备好的截图。

## 每位成员必须能解释

| 问题 | 应能说明的要点 |
|---|---|
| 为什么要四颗卫星？ | 单历元同时解ECEF三维位置和米制钟差四个未知数；四星还须几何满秩，且没有残差检验冗余。 |
| 钟差单位是什么？ | 状态量b=cΔt是米；全星相同伪距偏差主要被b吸收，不应逐星全剔除。 |
| 为什么要发射时刻与地球自转改正？ | 星历位置对应信号发射时刻，传播期间ECEF坐标系发生转动，必须统一接收时刻的坐标表达。 |
| 电离层和对流层怎么处理？ | 单频Klobuchar电离层与课程规定的Saastamoinen模型；不能用双频组合或真值代替。 |
| 普通解与改进解有什么区别？ | 基线独立等权LS；改进解检验残差一致性并比较候选子集，最终位置重新等权拟合保留的观测。 |
| 为什么要报告SUSPECT？ | 多个最小故障数候选都通过时证据不足；选择最低残差的候选不等于能正确识别故障。 |
| 检验为什么受σ影响？ | 统计量使用预设观测噪声尺度；低估σ会误报，高估σ可能漏检。压力测试展示失配失败。 |
| PDOP能保证精度吗？ | PDOP反映未加权几何放大，不包含模型误差和故障幅度；小PDOP或小残差都不保证真实误差小。 |
| 怎么证明算法没有偷看真值？ | core模块只接收星历、当前观测和算法配置；真值仅在运行结束后评价，故障参数在输入生成层。 |
| 为什么不能只报P95？ | P95在有有效解的要求定位历元上计算，必须同时给有效解比例与全体要求定位历元的10m内成功率。 |
| 创新在哪里？ | 多假设、可解释证据、状态回放、受控实验与可复现评价组成完整系统；基础方法与论文启发均标注来源。 |
| GNC是论文完整复现吗？ | 不是。只借鉴自适应连续化思想生成提议，最终由同一一致性检验确认；当前未获得默认方法以上的精度收益。 |
