# 第五轮：累计换星证据、几何失败诊断与完整复验

本轮已修改默认算法并完成全套工程测试、教师公开数据回归，以及115,843个新生成历元的新旧算法对照。**四星剩余几何状态问题已修复，换星识别有小幅改善；六星孤立首历元、部分换星星组、四/五星带故障精度仍未达标。不能宣布所有条件达到教师指标。** 没有改变普通解、教师接口、评分门槛或删除失败样本。

## 本轮实现

- `core/diagnosis.py`加入累计身份变化判断。原判断要求某一帧明确支持新身份，短窗有时仍被旧身份占据。新判断比较所有可能的后缀起点与其他单星身份，对候选数量和变化时刻做混合归一化，达到原20:1证据比、当前检验也支持新身份时截断旧证据。原来的一帧明确变化、候选被否定和带符号幅度创新判断仍优先。没有预设换星时刻，没有新增卫星专属门槛。
- 该分数使用拟合后的相对似然，是工程选择量，不是经校准的故障概率或完整性保证。重复使用数据、相关噪声和候选选择会影响统计解释；因此实际错剔、错误确认和误报同时报告。变化检测的一般思路可参见 [ION的序贯故障检测研究](https://www.ion.org/publications/abstract.cfm?articleID=6911)，本实现不是该论文算法的完整复现。
- `core/initialization.py`保留代数方程的实根、复根实部及模型域外候选，供失败诊断。原代码只保留域内实根，遇到复根或域外根时连几何证据也丢失。代数平方伪距方程依据 [Bancroft方法](https://gssc.esa.int/navipedia/index.php/Bancroft_Method)；复根实部用于诊断/重试是本项目的工程扩展，不是有效代数解。
- `core/solver.py`仅在改进解失败恢复路径使用这些候选。模型域外候选不输出位置；域内近似候选必须通过原完整物理模型收敛、截止高度角及几何检查。没有合格解且所有可计算候选都呈现严重差几何时，保留证据并返回`INVALID_GEOMETRY`；坐标等字段留空。健康几何仅因迭代次数不足失败，仍为`INVALID_CONVERGENCE`。候选PDOP是近似位置处的诊断量，不是有效定位结果的PDOP。
- 增加CLI消融开关`--disable-sequential-change-detection`和`--disable-complete-geometry-diagnosis`。两者关闭可对照第四轮行为。普通解四未知数、等权最小二乘、物理改正及输出列不变。

另一项实验尝试把连续偏差模型用于所有已报警的模糊身份归因。虽然部分冷启动改善，但旧开发数据快速换星强故障P95从26.216m恶化到32.051m，故**未合入默认实现**。完整实验保存于`runtime/diagnosis-iteration5/coherent-experiment.json`。没有只根据改善的指标选择方案。

## 六星实测：收益有限，失败仍在

下表为偏差绝对值≥30m的强故障段，正确标星包括暂定选择，不等于确认身份。所有六星组位置可用率100%。

| 场景 | 水平P95 / m | 10m内成功率 | 正确标星率 | 确认正确率 |
|---|---:|---:|---:|---:|
| 连续冷启动 | 5.765 | 96.13% | 97.02% | 86.13% |
| 阶跃 | 3.744 | 99.23% | 99.29% | 94.88% |
| 渐变 | 4.488 | 96.65% | 97.53% | 88.01% |
| 一次换故障星 | **50.989** | **94.49%** | 94.64% | 90.71% |
| 每15历元换故障星 | 3.601 | 97.14% | 97.38% | 86.07% |
| 冷启动最初10历元，280个 | 4.740 | 96.79% | 97.50% | 见完整记录 |
| 所有换星后的前10历元，1120个 | **18.789** | **94.20%** | 94.46% | 见完整记录 |
| 336个相互独立首历元 | **34.000** | **91.67%** | 91.96% | 70.83% |

同一新输入上，累计身份变化触发2次，快速换星强故障P95 **3.668→3.601m**，10m成功率**97.02%→97.14%**，错剔**45→43**；确认错剔仍2次。一次换星强故障P95 **51.049→50.989m**，错剔**106→105**，仍不达标。全部连续六星错剔277→274，确认错剔仍9次。孤立首历元没有历史，结果没有改善，26次错剔均为SUSPECT，确认错误0。

六星正常/共同偏差P95分别2.101/2.248m；共同偏差钟差P95=2.059m。正常误报0，共同偏差段1/2240为暂定误报。全部连续六星汇总P95=3.281m，但不能用这一结果覆盖一次换星失败。逐28个星组检查，连续冷启动3组、阶跃1组、渐变4组、一次换星4组、快速换星6组未同时达到强故障精度/成功率/标星率目标。

新不规则故障组汇总P95=3.426m，10m成功率99.00%，强故障正确标星99.49%，无故障段误报0，错误确认1次。随机切换、非线性、间歇故障的强故障P95分别3.952/3.846/3.895m，各组汇总通过；但具体星组仍分别有3/1/2组失败。该组新旧算法结果相同，本轮没有带来额外收益。开发种子650201的间歇故障P95=11.988m、成功率94.90%，失败也保留，不能只引用最终批通过。

| 可见集合变化 | 全部P95=2.518m；其中冷启动强故障P95=20.767m，成功率93.75% | 整体好不能掩盖冷启动段失败 |
| 数量变化/中断 | 0、3、4星状态140/140正确，无效字段为空 | 含四/五星故障的总体定位仍失败 |
| 2.4m高噪声压力 | 全部P95=27.517m，10m成功率89.76%，确认错剔169次；全部无故障误报4.69%，阶跃/渐变短纯净段11.07%/12.14% | 超过教师0.8m名义噪声，但仍如实保留为失败 |

四星恰定没有残差冗余，五星只有一个冗余量，报警后无法普遍验证唯一单星剔除。六星虽有两个冗余量，某些故障方向仍近共线。例如本轮一次换星失败G07与G20的方向夹角约0.30°，错误暂定选择造成57.09m水平误差。并非每个失败都只由身份歧义引起：某些正确剔星后的保留几何也导致超过10m误差。

参见 [ESA的RAIM可用条件](https://gssc.esa.int/navipedia/index.php/RAIM)及此前保存的[双状态不可辨识构造](../runtime/diagnosis-iteration3/cold-identifiability.json)：两个合规六星单故障位置相隔约128.6m，却产生相差约0.142m的均值观测，在0.8m噪声下无法同时保证10m精度。该构造说明不能承诺任意输入全面达标；它不替代或免除上面的实测失败。任务书同时要求准确表达证据不足、几何病态和观测不足，不能以固定高度、真值、未来观测或虚假状态规避。

## 复现

输出目录必须为空，程序拒绝覆盖已有证据：

```sh
uv run python scripts/validate_six_satellite.py --comparison iteration5 --suite continuous --seed 623281 --out runtime/recheck-v5-six
uv run python scripts/validate_six_satellite.py --comparison iteration5 --suite irregular --seed 623288 --out runtime/recheck-v5-irregular
uv run python scripts/validate_six_satellite.py --comparison iteration5 --suite four --seed 623285 --out runtime/recheck-v5-four
uv run gnss solve --input YOUR_INPUT.jsonl --out runtime/ablate-v5 --disable-sequential-change-detection --disable-complete-geometry-diagnosis
```

其余组与种子见冻结清单。本轮只处理算法、测试和技术验收记录，没有更新交付包、展示报告或演练材料。
